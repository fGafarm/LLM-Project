# v10出力結果の分析レポート

**分析日**: 2026-01-25
**対象**: 10社のv10出力結果（output_v10ディレクトリ）
**分析者**: Claude Code

---

## エグゼクティブサマリー

10社の有価証券報告書分析レポート（v10）を検証した結果、**重大な問題5件、中程度の問題3件**を発見しました。全体的なデータ品質スコアは平均88.7%（HIGH）ですが、以下の改善が必要です。

### 最優先課題
1. **XBRLデータの欠損問題**（重大度：HIGH）- 6社で主要指標がN/A
2. **データソース混在による誤情報**（重大度：HIGH）- 複数企業で同一の誤った情報が混入
3. **セグメントデータの検出不全**（重大度：MEDIUM）- 10社中10社で警告

---

## 1. 発見された問題の詳細

### 🔴 重大度：HIGH

#### 1.1 XBRLデータの欠損問題

**影響範囲**: 10社中6社（60%）

| 企業名 | 欠損している主要指標 | Confidence Score |
|--------|---------------------|------------------|
| 日本たばこ産業 (2914) | 売上高 | 89.7% (HIGH) |
| トヨタ紡織 (3116) | EBITDA, 自己資本比率, ROE/ROA/ROIC, 配当 | データなし |
| 日立製作所 (6501) | 売上高, 営業利益, EBITDA, 有利子負債 | 83.7% (HIGH) |
| ソニーグループ (6758) | 粗利率, 有利子負債, ROIC, 配当 | 95.7% (HIGH) |
| ファーストリテイリング (9983) | 売上高 | 79.2% (MEDIUM) |
| ソフトバンクG (9984) | 売上高, 営業利益, EBITDA | 83.7% (HIGH) |

**問題の詳細**:
- XBRLタグのマッピングが不完全で、主要KPIが取得できていない
- 特に売上高（NetSales/Revenue）のタグが企業によって異なる可能性が高い
- IFRSとJGAAP（日本基準）で使用されるタグが異なる

**影響**:
- レポートの有用性が大幅に低下
- 投資家が最も重視する指標が欠落している

---

#### 1.2 データソース混在による誤情報の生成

**影響範囲**: 10社中4社で同一の誤った情報を検出

**問題のパターン**:

##### パターン1: 「中国向けホタテ輸出」の誤混入
以下の企業で、水産業と無関係なのに同じ情報が記載されている:

- **日本たばこ産業** (たばこ製造)
  - 「今年起きたこと」に「中国向けホタテ輸出の増加 (P.4)」
  - 「売上高」の要因として「中国向けホタテ輸出の増加 (プラス) 約50億円 (P.4)」

- **日立製作所** (総合電機)
  - 「売上高」の要因として「中国向けホタテ輸出の増加 (プラス) 約50億円 (P.4)」

- **ソニーグループ** (総合エレクトロニクス)
  - 「売上高」の要因として「中国向けホタテ輸出の増加 (プラス) 約50億円 (P.4)」

- **任天堂** (ゲーム)
  - 「今年起きたこと」に「中国向けホタテ輸出の増加 (プラス) 約50億円 (P.4)」

**正しい記載**:
- この情報は**極洋（水産商社）**のみに関連する情報であるべき

**原因推定**:
- RAGシステムで類似文書が混在している
- プロンプトのコンテキスト制御が不十分
- 企業固有のコンテキストが適切に分離されていない

---

##### パターン2: 汎用テンプレート文の誤使用

複数の企業で同じフレーズが不適切に使用されている:

```
「原材料価格の高騰 → 価格転嫁を推進 (P.15)」
```

このフレーズが以下の企業で確認された:
- 信越化学工業 (P.15)
- ソニーグループ (P.15) ← 為替リスクセクションで不適切
- 任天堂 (P.15)
- ファーストリテイリング (P.15)
- ソフトバンクG (P.15)

**問題点**:
- ページ番号(P.15)が全て同じ → コピー&ペーストの可能性
- リスクセクションで一律に使用されており、企業固有の内容になっていない

#### 1.3 「今年起きたこと」セクションの精度問題

**問題のあるケース**:

##### ソニーグループ (6758)
```markdown
## 今年起きたこと（トップ3）
1. 当社株主に帰属する当期純利益は前年同期比1.8%増の937,126百万円に推移した。(P.2)
2. 売上高は前年同期比1.8%増の11,539,837百万円に推移した。(P.2)
3. 現金及び現金同等物期末残高は前年同期比1.8%増の2,049,636百万円に推移した。(P.2)
```

**問題点**:
- 「起きたこと」＝「出来事」を期待しているが、KPI数値の羅列になっている
- 期待される内容: 事業戦略の発表、M&A、新製品発売、組織再編など

**望ましい例（極洋）**:
```markdown
1. 中国向けホタテ輸出の増加 (P.4)
2. 国産クロマグロ養殖事業の出荷体制の安定化 (P.7)
3. 大規模な地震をはじめとする自然災害への備えとして、事業継続計画(BCP)の策定 (P.14)
```

**影響範囲**: 10社中10社（100%）

```

```

**実際の状況**:

- 例: 極洋（4セグメント）、JT（3セグメント）、ソニー（6セグメント）など

**問題点**:
- 品質検証プログラムがセグメントデータを正しく認識できていない
- マークダウンフォーマットの解析ロジックに問題がある可能性

## 4. 根本原因の分析

### 4.1 XBRLデータ欠損の原因

**仮説1**: 会計基準によるタグ名の違い
- IFRS採用企業: Revenue
- 日本基準企業: NetSales
- 米国基準企業: SalesRevenueNet

**仮説2**: 連結/単体の識別問題
- 連結財務諸表と単体財務諸表でタグが異なる可能性

**仮説3**: XBRLタクソノミのバージョン違い
- 2020年タクソノミ vs 2023年タクソノミで構造が異なる

### 4.2 データ混在の原因

**RAGシステムの問題**:
```
検索クエリ: "2023年の主要な出来事"
→ ベクトルDB検索で類似文書が混入
→ コンテキストに他社の情報が含まれる
→ LLMが誤って他社情報を使用
```

**プロンプトの問題**:
- 企業コード・企業名によるフィルタリングが不十分
- システムプロンプトに企業固有コンテキストの分離指示がない

## 5. 推奨される改善優先度

### Phase 1: 緊急対応（1週間以内）

1. **XBRLタグマッピングの拡張** 🔴
   - 売上高の複数パターン対応（Revenue, NetSales, SalesRevenueNet等）
   - IFRS/JGAAP/USGAAPの会計基準別タグ辞書作成
   - フォールバック機能の実装

2. **RAGフィルタリングの強化** 🔴
   - 企業コード (EDINETコード) による厳密なフィルタリング
   - クエリ生成時に企業固有の識別子を必須化
   - クロスコンタミネーション検出ロジックの追加

3. **品質検証の厳格化** 🔴
   - 主要KPI欠損時のConfidence自動低下（N/A → -30%ペナルティ）
   - データソース整合性チェックの追加

### Phase 2: 重要改善（2週間以内）

4. **セグメントデータ抽出の改善** 🟡
   - マークダウンパーサーの修正
   - セグメント情報の構造化データ生成

5. **「今年起きたこと」の精度向上** 🟡
   - プロンプトに「数値ではなく出来事を抽出」と明示
   - 事業セクションから重要イベントを優先抽出

6. **時系列データ取得の安定化** 🟡
   - XBRLから過去データが取得できない場合のエラーハンドリング
   - PDF抽出からのバックアップ取得

### Phase 3: 品質向上（1ヶ月以内）

7. **汎用フレーズの削減** 🟢
   - テンプレート文の使用を最小化
   - 企業固有の文脈に基づいた記述生成

8. **セグメント差異の詳細分析** 🟢
   - 15%以上の差異がある場合は詳細説明を追加
   - 調整項目の内訳を明示
